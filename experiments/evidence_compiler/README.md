# EXP-019 · 논지 조건부 공시 변화 엔진 (증거 컴파일러) — 사전등록

> 등록일 **2026-07-28** · 이 날짜가 전향 검증의 컷오프다.
> 이 문서에 적힌 임계값은 **검증된 값이 아니라 사전등록된 출발점**이다.
> 전향 데이터가 쌓이기 전에 임계값을 바꾸면 시행 카운터에 `searched`로 등록해야 한다.

## 0. 왜 이 구조인가 — 기각된 대안들

| 대안 | 기각 근거 |
|---|---|
| LLM이 자유형으로 BUY/SELL 출력 | Lopez-Lira–Tang의 효과는 소형주·롱숏·저비용 참여자에 집중, 2024년까지 Sharpe 급감. StockBench에서 대부분의 LLM이 동일가중 매수보유에 미달. 본 계좌는 장기·롱온리·저회전 |
| LLM으로 과거 백테스트 | 모델이 과거 금융정보를 암기했을 가능성 — 명시적으로 금지해도 누출 잔존. **과거 공시는 추출 정확도 평가에만 사용** |
| 가격 기반 자동매도 | 10전 10패 (CONCLUSIONS §3-4) |
| 기계 단독 선정 | 이벤트형(내부자) 기각, 상태형(GP/A) 검정력 부족 (§3-5) |

## 1. 가설

**알파 후보는 세 요소의 교집합에만 있다:**
사람의 비합의적 인과 논지 × 시장이 즉시 소화하지 못한 공시의 미묘한 변화 × 수십 기업을 일관 비교하는 LLM의 처리량.

공시 문구 변화에 지연 반영되는 정보가 있다는 선행 근거: [Lazy Prices (Cohen–Malloy–Nguyen)](https://www.nber.org/system/files/working_papers/w25084/w25084.pdf).
이것은 검증할 **장소**를 알려줄 뿐, LLM 알파를 보장하지 않는다.

## 2. 구조 — 역할 분리가 전부다

```
시점 고정 공시 → LLM 증거 추출 → 결정론적 점수·순위 → 매수·교체 규칙 → 별도 주문 시스템
   (EDGAR)      (구조화 출력만)     (코드)              (코드)          (LLM 접근 불가)
```

LLM에게 **주지 않는 것**: 주가, 포트폴리오 손익, 주문 권한.
LLM에게 주는 것: 최신 공시 + 직전 공시 + 등록된 논지 스키마. 그게 전부다.
숫자 계산·포지션 크기는 전부 코드가 한다 — LLM의 수치 추론은 작은 숫자 변경에도 불안정하다
([Chicago Booth](https://www.chicagobooth.edu/research/center-for-applied-artificial-intelligence/research/our-faculty-research/2025/caution-ahead-numerical-reasoning-and-look-ahead-bias-in-ai-models)).
모델·프롬프트·스키마 버전은 고정하고 기록한다.

## 3. 파이프라인 구성 요소 (이 디렉터리)

```
theses/*.json        사람이 사전등록하는 논지 — 인과 노드·관찰 가능 KPI·반증·기한
                     (§6 판단 필드 7종 + 인과 사슬. "AI 성장" 같은 문장은 노드가 될 수 없다)
fetch_filings.py     EDGAR 10-K/10-Q/8-K을 접수시각(acceptance) 기준으로 저장 — point-in-time
evidence.py          증거 레코드 스키마 + 결정론적 검증기
                     · 인용문이 원문에 실제로 존재하는가 (코드로 검사)
                     · 숫자가 포함되면 XBRL 참조 또는 review_required 강제
                     · theme_node가 등록된 논지에 실재하는가
evidence/*.json      LLM이 산출한 증거 레코드 (검증기를 통과해야만 점수 계산에 진입)
```

증거 레코드 형식 (자유형 의견 금지):

```
theme_node · direction(confirm|disconfirm|neutral) · delta(new|strengthened|weakened|removed)
source_accession · exact_source_span · xbrl_fact_ids · review_required
```

## 4. 초기 매매 규칙 (사전등록 출발점 — 전부 미검증)

```
매수      서로 다른 논지 노드에서 확인 증거 ≥ 2 · 치명적 반증 없음 · 비LLM 숫자 품질 기준 통과
          · 승인 후보군 상위 20% · 공시 공개 후 고정 지연 두고 다음 세션 실행
          · 최초 검증에서 E1 미사용 (정보 신호 확인 후 별도 실행 실험으로 추가)
유지      약한 부정 변화 1회 → 매도하지 않고 신규 매수만 중단
          가격 목표 · 이동평균 · 트레일링 스톱 사용 금지
정상 교체  두 번 연속 공시 사이클에서 순위 하위 50% + 상위 20% 신규 후보 존재
          → 매도와 신규 매수를 한 쌍으로 실행 (현금으로 이탈하지 않음)
긴급      사전등록된 치명적 반증을 LLM이 탐지 → 자동매수 정지 → 사람이 원문 확인
          → 정해진 다음 거래 창에서 청산. LLM은 주문을 제출하지 않는다
중립      신호가 없으면 채우지 않는다. 알파 슬리브의 중립 상태는 현금
```

**Level 4 정합**: 이 실험 슬리브는 페이퍼로만 돈다. 실계좌 반영 시 매수는
"제안 → 사람 승인(arming)"을 거친다 (CONCLUSIONS §2, 2026-07-28 결정).

## 5. 검증 설계 — 핵심 비교는 하나뿐

| 군 | 내용 |
|---|---|
| Q | 숫자 기반 엔진 (수익성·발생액·희석·자산증가) — fetch_fundamentals.py 확장 |
| Q+L | 동일 엔진 + LLM 공시 변화 신호 |
| Control | 업종·규모·베타·사전수익률 매칭 통제군 |

> **주 가설: Q+L이 비용·세금 후 Q보다 나은가?** (SPY 비교는 LLM 기여를 식별하지 못한다)

사전 고정: ① 2026-07-28 이후 전향 데이터만 수익 검증에 사용 ② 모델·프롬프트·특징·보유기간
사전 고정 (보유기간 = 다음 공시 사이클 1개, 복수 기간 중 사후 선택 금지) ③ 접수시각 기준
point-in-time ④ 후보군 수십 종목 이상 ⑤ 스프레드·시장충격·세금 포함 ⑥ 겹치는 수익률과
공통 충격을 고려한 블록 부트스트랩 ⑦ 판정 문턱은 판정 시점의 시행 카운터 값.

## 6. 실패 시 처분 (사전 약속)

Q+L이 Q를 이기지 못하면: LLM은 공시 모니터링·반증 탐지·연구 감사로 한정하고(그 자체로
소환장 피드의 구현이다), 선정은 결정론적 요인에 맡기며, 실행 프로토콜은 비용 절감 역할로
남긴다. **엔진이 실패해도 인프라(논지 등록·point-in-time 저장소·검증기)는 §11의 3~4단계
그 자체이므로 버려지지 않는다.**
