# 분봉 전략 재설계 구현·검증 기록

## 상태

새 연구·검증·모의운용 연결 경로를 구현했다. 실제 분봉 이력으로 수익성이 입증된 전략은 아직 없다. 데이터 최소 조건과 실시간 관찰 조건을 충족하기 전에는 모의운용 자격을 부여하지 않는다.

기존 일봉 전략은 참고자료다. 이전 일봉 재현의 수익률을 새 단타 전략의 성과로 인용하지 않는다. 기존 모의운용 원장과 신규 연구·모의운용 원장은 별도로 사용한다. 기존 원장에 새 전략을 덮어씌우는 이관은 제공하지 않는다.

## 구현 내용

- `paper/intraday/data.py`: UTC 정규화, 출처·이용 조건·가용 시각, 당시 유니버스, 틱 발생/수신 시각을 저장하는 SQLite 원장. 완료 봉 수정과 충돌하는 이벤트 ID를 거부한다.
- `strategy.py`: 거래량 동반 돌파, 상승 추세 눌림 회복, 장중 과잉 반응 후 VWAP 회귀. 각각 두 설정만 사전 선언했다. 학습 구간의 비용 차감 기대 R을 공통 순위 기준으로 사용한다.
- `replay.py`: 분봉 도착 순서에 따른 재현, 정수 수량과 참여율, 진입 지연, 불리한 손절 갭, 부분 체결, 완결된 왕복 거래 집계. 분봉 가정 체결은 틱 검증과 구분한다.
- `evaluation.py`: 90/30/60거래일 분할, 선택 결과 고정 후 검증, 전체 탐색 이력, 편도 5/10bps, 지연·절반 체결·미체결 민감도, 거래일 블록 검정과 반복 관찰 보정.
- `stream.py`, `collection.py`, `shadow.py`, `advisor.py`: 모의 시세 전용 KRX 틱·호가 수집, 주문 없는 관찰, 당시 AI 입력/응답 보존, 규칙 단독과 AI 예산 조정의 병렬 재현. 호가 접촉만으로 체결시키지 않는다.
- 기존 모의운용 최종 위험 검사에 자격·버전·유니버스·틱/호가 신선도, 비용 차감 목표 수익, 예약 손실, 당일 1%와 누적 낙폭 5% 중단을 추가했다. 최고 자산과 중단 상태는 재시작·버전 변경으로 지워지지 않는다.

자격 부여는 주문 활성화가 아니다. 실거래·시장가·자동운용 기본값은 계속 비활성이다. 기존 위험 검사, 주문 상태, 중복 방지, 대사와 감사 경로를 사용한다.

## 실행 경로

아래 경로들은 저장소 밖의 별도 실험 디렉터리를 사용한다. 실제 API 인증 정보는 문서나 소스에 기록하지 않는다.

1. 검증된 무료 분봉·당시 유니버스 자료를 정규화한 번들을 가져온다.

   `python -m quantpilot.jobs.collect_intraday_data --ledger <historical.sqlite3> --mode external_historical --input <bundle.json>`

2. 고정된 전체 연구를 재현한다.

   `python -m quantpilot.jobs.run_intraday_backtest --ledger <historical.sqlite3> --experiment <research.sqlite3> --output <backtest.json>`

3. 명시적으로 모의 시세를 수집하고, 고정된 후보가 있으면 주문 없는 관찰을 기록한다.

   `python -m quantpilot.jobs.collect_intraday_data --paper --seconds 23400 --ledger <realtime.sqlite3> --experiment <research.sqlite3> --security-master <security-master.json>`

4. 보고서에 나온 데이터 해시와 전략 ID로 평가한다. 평가할 때마다 관찰 차수를 남긴다.

   `python -m quantpilot.jobs.evaluate_intraday_candidate --experiment <research.sqlite3> --strategy trend_pullback --dataset-hash <hash>`

5. 모든 조건을 통과한 경우에만 같은 평가 명령에 `--admit-runtime <새 모의운용 디렉터리>`를 붙여 버전을 등록할 수 있다. 주문은 시작되지 않는다. 이후 시세 수집의 `--paper-runtime`을 그 디렉터리에 연결하면 원장에 검증된 시세와 유니버스 상태를 제공한다. 기존 모의운용 시작·권한 절차는 유지된다.

낙폭 중단 후 검토는 `python -m quantpilot.paper --runtime-dir <경로> review-drawdown --reason "검토한 원인과 조치"`로 기록한다. 포지션과 미결 주문이 없는 정지/일시정지 상태에서만 가능하고, 별도 재개 전에는 주문을 시작하지 않는다.

보통주 자격은 거래량 순위만으로 추정하지 않는다. 종목 마스터 JSON은 `as_of`, `source`, `license`, `license_verified: true`, `securities`를 가진다. 각 종목에는 `symbol`, `market`(KOSPI/KOSDAQ), `instrument: common_stock`, `suspended: false`가 필요하다. 수집 시점 24시간 이내의 검증된 자료만 사용한다. 확인되지 않은 종목은 자격 미확인으로 남는다.

## 검증 증거와 한계

- 전체 검증: `scripts/verify-paper.py` — 1,548 passed, 2 skipped (97.06초). 스모크는 broker=mock, live_trading_enabled=false, 자동 운영 비활성 상태를 확인했다.
- `tach check`: 통과. 연구 노트와 거래 코드의 기존 경계 유지.
- 빈 데이터셋의 실제 CLI 실행: `data_insufficient`, 관측 0거래일 / 요구 180거래일. 데이터 해시 `b7bfcce18ba4fce7aa8b2befa63b640523d9d30952c655909858c62c9f298382`.
- 실제 장기 분봉+당시 유니버스 자료, 전략별 검증 완료 왕복 100회, 고정 후 실시간 20거래일은 미충족이다. 새 전략의 순이익·Sharpe·승률을 실측한 것으로 제시하지 않는다.
- 틱 체결은 주문 없는 보수적 추정이다. 1초 지연, 엄격한 가격 통과, 틱 수량 1%와 호가 수량 한도를 사용한다. 실제 대기열 위치는 알 수 없다. 전략별 완결된 틱 재현 거래가 하나도 없으면 관찰 기간만으로 자격을 얻지 못한다.
- 유료 데이터, 실전 시세 자동 전환, 실제 주문, Slack 전송, commit/push/PR은 실행하지 않았다.
- 180거래일의 희소 합성 자료로 실제 연구 엔진을 통과시켰다. 6개 탐색 결과·3개 고정 후보가 생성되었고 반복 실행 결과가 같았다. 세 후보 모두 `data_insufficient`로 남았다. 이 검사는 연구 절차의 통합 검증이며 시장 수익성 증거가 아니다.
- 실행 코드의 의미를 해시로 묶어 버전에 반영한다. 규칙·집행·위험 로직 변경 시 이전 자격으로 신규 진입할 수 없다. 이미 보유한 포지션은 버전 불일치나 봉 오류가 있어도 기존 주문 경로로 보호 청산한다.
- 늦게 수신한 주문 결정 이전 틱은 체결에서 제외한다. 부분 매수 후 보호 청산 조건이 생기면 남은 매수를 취소한다. 수량이 0인 호가는 그대로 기록하고 체결 유동성으로 계산하지 않는다.
- 날짜 경계에서 전날까지 반영한 슬리피지가 다음 날 손실로 다시 잡히지 않도록 비용 차감 자산을 이어받는다. 날짜 전환 회귀 테스트로 검증했다.
- 반복 관찰의 유의수준이 낮아질수록 재표본 횟수도 늘린다. 고정된 9,999회 때문에 6번째 평가부터 통과가 불가능해지던 수치 정밀도 문제를 수정했다.
- 지연 수신 후 손절선을 변경한 경우, 이미 지나간 봉 저가에 새 손절가를 소급 적용하지 않는다. 분봉만으로 선후관계가 모호하면 품질 문제를 기록하고 자격을 보류한다.
- 독립 검토에서 제기한 실행 정책 결합, 갭 민감도 보고, 매도 버전 귀속 검사를 보강하고 전체 회귀를 통과했다. 미완성 5분봉 지적은 기존 집계 함수가 다섯 구성 봉이 모두 있는 묶음만 반환한다는 근거와 회귀 테스트로 확인했고, 보호 함수에도 완료 시각 검사를 명시했다. 수정 사항의 최종 재검토는 PASS로 완료했다.
- 승인 경로는 정책·원장 자본·현금을 500만 원으로 확인하며 다른 자본은 변경 없이 거부한다. 정상 500만 원 승인과 300만 원 거부를 실제 admit 호출로 검증했다.
- 승인된 실행 정책에는 편도 10bps 슬리피지와 검증한 수수료·세금·위험 한도·시간 설정을 고정한다. 분봉 재현·틱 재현·전략 비용은 같은 정책 상수를 참조한다. 승인 후 해당 설정 변경은 거부되며 최종 진입 검사도 일치를 확인한다. 갭 민감도는 실제 관측 갭에 더해 손절 체결가격을 50bps 불리하게 조정한 스트레스 결과다.

## 설계 근거

파운데이션 볼트의 기술적 분석 연결 노트, Harris 성과 평가 장, Sullivan·Timmermann·White의 데이터 스누핑 노트, Harvey 등의 다중 검정 노트, 집행과 비용 통합 노트를 검토했다. 기술적 규칙은 검증할 가설로 취급하고, 당시 가용 정보·전체 탐색 이력·비용·미체결을 보존하는 데 반영했다. 볼트의 설명을 KRX 분봉 수익성의 증거로 대체하지 않았다.

KIS 인터페이스는 [공식 KRX 실시간 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/domestic_stock/domestic_stock_functions_ws.py)와 [공식 모의 환경 설정](https://github.com/koreainvestment/open-trading-api/blob/main/kis_devlp.yaml)을 확인했다. 구현은 공개 시세 TR 두 종류로 제한한다.

## 최종 독립 검토

Anthropic 검토자가 초기 지적과 두 번의 수정 검토를 거쳐 남은 차단 사유가 해소되었음을 확인했다. 최종 판정은 PASS다. 정적 소스·변경분·회귀 테스트 코드에 대한 독립 검토이며, 테스트 실행은 구현 담당자가 동일 코드에서 별도로 수행했다. 최종 검증은 1,548 passed, 2 skipped, 모의 스모크와 tach check 통과다. 원본 검토 영수증과 파일 해시는 [구현 증거](plans/intraday-implementation-receipt.json)에 보존했다. 시장 데이터 최소 조건은 여전히 미충족이며 주문을 활성화하지 않았다.
