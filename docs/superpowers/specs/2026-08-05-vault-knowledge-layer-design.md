# 볼트 지식 계층 설계 — 검색 MCP + 사용 규약

작성 2026-08-05 · 상태: 승인됨(사용자), 구현 진행 중

## 왜 하는가

`quantpilot-foundation/` 볼트는 책 20권과 논문 69편, 노트 **551편**을 같은 규격(3줄 요약 →
설명체 본문 → 접힌 근거 장부)으로 담고 있다. (홈 노트가 적은 "16권·405편"은 R3 시점 수치이고,
그 뒤 Hasbrouck 실증 미시구조·López de Prado 금융 머신러닝·Murphy 기술적 분석·Ang 팩터 투자가
더해졌다.) 홈 노트가 스스로 선언한 목표는 "사람이 읽는
서재이자 **LLM이 매매·시황 판단의 근거를 인용하는 창고**"인데, 후자가 아직 작동하지 않는다.
사용자가 "볼트 봐"라고 지시할 때만 열람되므로 사실상 열람용 위키에 머문다.

문제는 검색 기술이 아니라 세 가지다.

1. **트리거** — 언제 볼트를 봐야 하는지 에이전트에게 알려주는 장치가 없다.
2. **탐색** — 449편에서 어디를 볼지. MOC·개요·위키링크로 절반은 이미 해결돼 있다.
3. **책임** — 봤다는 증거가 없다. 인용 없는 답변은 파라메트릭 지식과 구별되지 않는다.

이 설계는 셋을 각각 다른 계층으로 처리한다.

## 채택 근거

OSS 후보 12종을 조사해 **obsidian-hybrid-search**(flowing-abyss, MIT)를 채택하고,
사용자 결정에 따라 **포크 + 최소 패치**로 운용한다.

채택 이유:

- 기본 임베딩이 `Xenova/multilingual-e5-small`(117MB, 100개 언어, 완전 로컬) — 한·영 혼용
  볼트에 맞는 유일한 즉시 사용 가능 후보. 탈락한 다수 후보(Basic Memory, Smart Connections,
  Qdrant MCP)는 기본 임베딩이 **영어 전용**이었다.
- BM25(제목 10배·별칭 5배 가중) + 퍼지 제목 + 벡터 KNN을 RRF로 융합, 다국어 크로스인코더
  리랭커(`bge-reranker-v2-m3`) 선택 적용.
- **위키링크·백링크 그래프 탐색**과 frontmatter 필터를 지원 — 이 볼트가 이미 갖춘 MOC·연결
  구조를 그대로 활용한다. 반대로 LightRAG류 GraphRAG는 큐레이션된 위키링크를 버리고 LLM으로
  그래프를 재구축하므로 449편 규모에서 비용 대비 손해.
- 옵시디언 실행 불필요(폴더 직접 읽기). 인덱스가 SQLite 단일 파일이라 후속 런타임 단계에서
  Python이 같은 인덱스를 읽을 수 있다.
- 유사 벤치마크가 공개돼 있다: Andy Matuschak 에버그린 노트(1,357편, 내부 링크 5,000개 이상,
  golden query 78개)에서 nDCG@5 0.722 / Hit@1 0.795. 이 볼트와 성격이 가깝다.

기각: **qmd**(28.6k★, 검색 품질 우위)는 Windows 설치 마찰이 이슈로 문서화돼 있고 모델
다운로드가 ~2.2GB라 첫 수의 리스크가 크다 — 업그레이드 경로로 유보. **커스텀 자작**은
"바퀴를 재발명하지 말자"는 원칙에 어긋나며, 볼트 특화 요구가 실제로 확인된 뒤에나 정당하다.

**아카이브 주의**: `obsidian-mcp-tools`(833★)는 2026-05-13 아카이브됐다. 옛 가이드가 여전히
추천하므로 채택 금지.

## 패치 (최소주의)

포크에 가한 변경은 둘뿐이다. 둘 다 이 환경 고유의 제약에서 나왔다.

1. **`src/config.ts` — `OBSIDIAN_DB_PATH` 지원.** 원본은 인덱스를 볼트 루트에 두는데, 이
   볼트는 OneDrive 안에 있다. 동기화 중인 폴더에 살아 있는 SQLite WAL을 두면 잠금 충돌과
   충돌 사본이 생긴다. CLI에는 `--db` 플래그가 있으나 **MCP 서버 경로에는 override가 없어**
   env var 추가가 필요했다. `config`가 모든 값을 getter로 노출하는 구조라 4줄 수정으로
   CLI·MCP·워처 전 경로에 일괄 적용된다.
2. **`src/db.ts` — DB 부모 디렉터리 자동 생성.** 인덱스가 볼트 밖으로 나가면 최초 실행 시
   디렉터리가 없어 better-sqlite3가 실패한다.

의도적으로 하지 않은 것: 검색 알고리즘·가중치 손질. 제목 10배 가중과 frontmatter 필터가
이미 있으므로, 골든 쿼리로 실패를 확인하기 전에는 건드리지 않는다.

## 운영 설정에서 반드시 필요한 두 가지 (구현 중 발견)

둘 다 기본값 그대로 두면 조용히 잘못된 결과가 나온다.

1. **`OBSIDIAN_RESPECT_GITIGNORE=false`** — 이 저장소는 볼트를 git 미추적으로 유지하려고
   `.gitignore:34`에서 `quantpilot-foundation/`을 제외한다. 도구 기본값은 `.gitignore`를
   존중하므로, 그대로 색인하면 **449편 전량이 조용히 누락**된다.
2. **`OPENAI_API_KEY=""`로 덮어쓰기** — `embedder.ts:277`의 `useApiMode()`가
   `!!(apiKey || OPENAI_BASE_URL)`이고 이 환경에는 `OPENAI_API_KEY`가 이미 설정돼 있다.
   덮지 않으면 **개인 장서 449편 본문이 원격 임베딩 API로 전송**된다. 빈 문자열은 falsy이므로
   로컬 모델로 강제된다.

## 사용 규약 (`vault-consult` 스킬)

MCP는 "찾는 능력"만 준다. 조사 결과 어떤 서버도 선제적으로 지식을 밀어주지 않는다 —
**능동성은 프롬프트 계층의 문제**다. 스킬이 담는 것:

- **트리거**: 퀀트·리스크·시장구조·전략·예측 질문, 그리고 그 영역의 코드 작업(리스크 게이트,
  백테스트, 집행). 그 외 작업에서는 침묵한다.
- **절차**: `search` → 상위 노트 정독 → `[[노트명]]` 인용. MCP 미기동 시 Grep + MOC 폴백.
- **선제 지적**: 해당 영역 작업 시작 시 1회 검색, 설계와 충돌하는 원칙 발견 시 지적.
- **성장 규약**:
  - 공백·충돌 → 미결 질문 노트 / meta 획득 큐에 기록.
  - 종합 노트는 **기존 장 노트 인용만으로** 구성하고 frontmatter에 에이전트 작성 표시와 근거
    노트 목록을 남긴다. 원천 주장은 사람이 검증한 노트에만 존재하고 에이전트는 그 위의 조합만
    담당하므로 감사 경로가 끊기지 않는다.
  - runbook 관할 노트(장·개요·연결)는 생성·수정 금지.

### 해결된 문제 — 프런트매터 YAML 오류로 색인되지 않던 17편 (2026-08-06 수정)

색인이 처음에 **534 / 551**에서 멈췄다. 남은 17편은 느린 것이 아니라 **파싱에 실패**했다.
원인은 하나였다: 프런트매터 값 안의 콜론+공백이 따옴표 없이 들어가 YAML이 중첩 매핑으로
읽었다.

```yaml
책: Forecasting: Principles and Practice        # 깨짐
책: "Forecasting: Principles and Practice"      # 고침
```

해당 노트(모두 같은 원인):

- `Forecasting Principles and Practice — 예측 실무 (Hyndman·Athanasopoulos 3e)/` 11편 전량
  (`책: Forecasting: Principles and Practice`)
- `논문/` 6편 — Kahneman·Tversky 1979 전망이론, Fama 1970 효율적 자본시장,
  Kelly 외 2018 특성은 공분산이다, Chang 외 2016 전문가 정치 판단,
  Hassan 외 2019 기업 수준 정치위험, Hirshleifer 2020 사회적 전달 편향
  (영문 부제에 콜론이 있는 논문들)

이는 검색 계층이 만든 문제가 아니라 **볼트의 기존 결함**이었고, Obsidian 속성 패널과
프런트매터 기반 질의에도 같은 영향을 주고 있었다.

**수정 절차 (사용자 승인 후 실행, 2026-08-06)** — 볼트는 git 추적 밖이라 되돌리기가 어려우므로:

1. 17편을 scratchpad에 백업.
2. 포크의 `yaml-fix.mjs`로 문제 줄만 따옴표 처리 (dry-run으로 계획 확인 후 적용).
   값의 내용은 바꾸지 않고 따옴표만 추가한다.
3. 백업과 **바이트 단위 diff**로 파일당 정확히 한 줄만 바뀌었는지 검증.
4. `reindex` → `yaml-check.mjs`로 누락 0 확인.

작업 중 걸러낸 함정: 첫 시도에서 스크립트가 프런트매터를 split/join으로 재조립하는 바람에,
**줄바꿈이 섞여 있던 노트 한 편**(`논문/Chang 외 2016`)의 CRLF/LF가 통일되어 9줄이 추가로
바뀌었다. 검증이 줄바꿈을 정규화해 비교한 탓에 스크립트 자체 가드는 이를 놓쳤다. 원본 줄
바꿈을 보존하는 in-place 치환으로 고치고 백업에서 되돌려 재적용했다. 최종 상태는 17편 모두
한 줄 변경이다.

결과: **551 / 551 색인, 누락 0.** 그동안 검색되지 않던 노트가 정상 조회된다 — "지수평활과
ETS 모형" → `08장 지수평활`, "전망이론의 손실회피" → `Kahneman·Tversky 1979`,
"효율적 시장 가설의 세 형태" → `Fama 1970`.

재확인 도구: 포크의 `yaml-check.mjs`(미색인 노트와 원인), `gap-check.mjs`(디스크 대조),
`yaml-fix.mjs`(수정, 기본은 dry-run).

### 알려진 제한 — 색인 처리량

링크가 조밀한 노트(`주제 MOC/`, `종합/`, `홈.md`, 상호참조가 많은 `논문/`)는 색인이 느리다.
빈 DB에서 일반 장 노트는 분당 20편 이상이지만 이 구간에서는 분당 1편 수준으로 떨어진다
(링크 해석 비용으로 추정 — 처리 중 `links`가 1,161 → 2,110으로 급증했다). 실용상 문제는
아니다: MCP 서버가 기동 시 이어서 색인하고, 검색은 색인 중에도 동작한다.

작업 중 관찰한 함정: 재색인을 **동시에 두 개 띄우면** 같은 SQLite에 경합이 생겨 처리량이
더 무너진다. 한 번에 하나만 돌린다.

## 범위 밖

QuantPilot 런타임 통합(다음 단계), claim ID 강제 인용, 임베딩 업그레이드(`bge-m3` — 골든
쿼리 실패를 확인하기 전에는 금지), 볼트 노트 개편, 새 Python 의존성.
