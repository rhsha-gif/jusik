# 9월 14일 모의 단타 안정화

사용자가 승인한 범위는 운영 안정화다. `legacy` 전략과 별도의 `intraday_v2` 연구를 유지하고 전략 최적화나 전환을 포함하지 않는다. 실거래, 시장가, 일반 자동운용 기본값은 계속 비활성이다.

## 구현 계약

1. **진단·종가**: 단계·안전한 오류 분류·HTTP/TR·대기와 처리 시간, 진입 차단 사유 및 지속 시간을 남긴다. 장애의 해제는 같은 하위 시스템에만 적용한다. 날짜별 종가 관측을 보존하며 후속 조회 실패가 유효 종가를 지우지 않는다. 직전 거래일 기준은 거래소 달력을 사용하고 기존 명시적 보정은 보존한다.
2. **요청 예산·대사**: 저장소 밖 SQLite에서 동일 모의 API 자격의 프로세스가 1.05초 간격을 공유한다. 보호 조회·취소·매도, 대사, 신규 진입, 후보 조회 순서다. 보유·주문이 있으면 10초, 없으면 60초 대사하고 주문 변화와 체결 통지가 깨운다. 미상 주문은 POST를 재전송하지 않는다. 대기 후 실제 전송 직전에 권한·시세·손실·시간 조건을 다시 검사한다.
3. **하이브리드 시세**: 후보 20개 체결 틱과 보유·미체결·상위 5개 후보 호가, 계좌 체결 통지를 합쳐 40개 이내다. 구독 해제 확인 후 슬롯을 재사용한다. 호가가 신선하지 않으면 REST로 조회하고, 전략 분봉은 REST 기준이다. 계좌 통지는 암호를 해독한 뒤 대사 힌트만 전달한다. 원래 사건 시각과 수신 시각을 남기며 1초 이내 시계 오차만 정규화한다.
4. **분봉 확정**: 잠정 관측은 수정 가능하며 종료 후 15초와 품질 조건을 만족해야 판단 이력에 들어간다. 확정 후 수정은 원본을 보존하고 해당 거래일 신규 진입을 격리한다. 보유분 보호에 필요한 후속 데이터는 계속 수집한다.
5. **감시 프로세스**: trader·AI worker·reporter만 소유한다. 종료 후 30/60/120초, 역할별 하루 최대 3회 재시작한다. 180초 heartbeat 정지 시 정상 종료를 먼저 요청하고 직접 소유한 자식만 제한적으로 종료한다. 당일 재개 권한·대사·시세·기준·위험 조건을 모두 통과해야 진입이 가능하다. 수동 정지·손실 정지·다음 날 재개 권한을 보존한다. OS 부팅 자동 실행은 범위 밖이다.
6. **보고·복기**: 독립 reporter가 마감 후 60초 이내 운영 숫자를 만든다. 미확인 종가를 명시하고 확인 후 한 번 정정한다. AI 복기는 별도이며 1분·5분 후 재시도, 최대 3회다. 제공자별 실패와 실제 실행기 사용 가능 여부를 보존한다. 발송 결과 미상인 Slack 메시지는 재전송하지 않는다.
7. **운영 전환**: 기능은 모의 프로필의 명시적 선택이다. 기존 자금 500만원·동시 1종목·종목당 10%·거래 위험 0.1%·일 손실 1%·낙폭 5%를 보존한다. 추가형 스키마 변경 전에 백업하며 기존 주문·체결·감사 이력을 보존한다. 롤백은 일시정지·대사 후 REST 모드 전환이고, 과거 원장을 새 체결 위에 복원하지 않는다.

## 검증 및 인수

오프라인 fake transport/socket/clock으로 다중 프로세스 간격, 우선순위, 대기 후 만료, 암호화 통지·중복·미확인 구독·단절, 확정봉 수정, 대사 실패 중 보호, crash 후 중복 POST 방지, 날짜 전환, AI 실패와 보고 중복 방지를 검증한다. 전체 `scripts/verify-paper.py`와 `tach check`, 구현자와 다른 제공자의 안전 검토를 완료한 뒤 운영 적용 결과를 별도로 기록한다.

**4개 완전한 거래일 인수는 실제 적용 이후의 절차다.** 중복 주문·체결·설명되지 않는 현금/수량 차이, 조기 분봉 확정, API 예산 위반이 없어야 한다. 기준 누락·임의 수동 보정이 없어야 하며 장애 수동 개입은 4일 및 주간 기준 최대 한 번이다. 매일 운영 보고와 AI 종료 상태가 있고 장 종료 시 보유·미체결이 없어야 한다. 수익률 기준은 사용하지 않는다.

## 참고한 설계와 의존성

- [한국투자 공식 예제](https://github.com/koreainvestment/open-trading-api/tree/b4e6249714418aa57833d1cbbbced39cbcc5b125): TR·통지 필드와 구독 계약 참고. 전체 라이브러리를 채택하지 않는다.
- [python-kis](https://github.com/Soju06/python-kis): 재구독 및 호출 경계 참고. 주문 POST 재시도 패턴은 이식하지 않는다.
- [NautilusTrader 대사](https://nautilustrader.io/docs/latest/concepts/execution/): 미완료 증거를 잔고 0으로 간주하지 않는 설계 참고. 프레임워크나 합성 체결은 도입하지 않는다.
- `cryptography==50.0.1`을 paper 선택 의존성에 고정했다. [공식 변경 기록](https://cryptography.io/en/latest/changelog/#v50-0-1)의 수정 사항과 Windows/Python 호환 배포를 확인했다. AES 구현을 직접 작성하지 않는다.

## 진행 기록

구현과 오프라인 통합 검증 완료. 전체 1,760개 검사와 smoke·tach를 통과했고, 독립 안전 검토의 지적을 수정한 뒤 최종 PASS를 받았다. 이후 사용자가 신규 진입 가동까지 승인하여 운영 의존성 갱신·원장 백업·정책 v5 적용과 조회 전용 대사를 완료했다. 감독 프로세스 시작은 HTS ID의 로컬 입력을 기다리며, 다음 세션의 점검과 조건부 재개를 후속 실행으로 연결했다. 실제 체결 통지와 4거래일 인수는 남아 있다. 위임 원본과 영수증은 저장소 밖 `~/.codex/paper-stability-modules-plan.json` 및 해당 격리 작업 트리의 `.aorch/task-runs`에 있다. 세부 증거와 운영 인수의 남은 조건은 [검증 기록](2026-09-14-paper-stabilization-verification.md)에 기록했다.
